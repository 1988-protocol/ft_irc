# 📋 ft_irc 다중 컴퓨터 접속 및 동료평가 가이드 (Evaluation Guide)

본 문서는 **42 동료평가(Peer Evaluation)** 시 평가자 및 피평가자가 서로 다른 컴퓨터(또는 여러 터미널)에서 다중 접속 환경을 구성하고, 필수 요구사항 및 동작을 빠르고 정확하게 검증할 수 있도록 정리한 실전 가이드입니다.

---

## 🖥️ 테스트 환경 구성

* **컴퓨터 A (서버 PC / 피평가자)**: `ircserv`를 실행하여 포트를 열고 대기하는 호스트
* **컴퓨터 B (클라이언트 PC / 평가자)**: 같은 네트워크(클러스터/Wi-Fi)에서 접속하는 유저/평가자

---

## 1. [1단계] 서버 컴퓨터(PC A) 준비 및 실행

### 1-1. 프로젝트 빌드
```bash
make
```

### 1-2. 서버 컴퓨터의 네트워크 IP 확인
터미널에 아래 명령어를 입력하여 다른 컴퓨터에서 접속할 **진짜 IP(src 뒤의 IP)**를 확인합니다.
```bash
ip route get 8.8.8.8
# 출력 예시: 8.8.8.8 via 10.12.0.1 dev eth0 src 10.12.3.45 uid 1000
# 👉 여기서 "src" 뒤에 적힌 IP(예: 10.12.3.45)를 기록합니다.
```

> 💡 **IP 선택 팁**: 도커나 가상머신이 만든 가상 IP(`172.x.x.x` 등)가 아닌, 같은 망에 물려있는 **`10.x.x.x`** 또는 **`192.168.x.x`** 대역의 IP를 사용해야 합니다.

### 1-3. 서버 실행
포트 번호(예: `6667`)와 비밀번호(예: `1234`)를 인자로 주어 실행합니다.
```bash
./ircserv 6667 1234
```
> 콘솔에 `[server] 포트 6667 에서 대기 시작`이 출력되면 준비 완료입니다.

## 2. [2단계] 클라이언트 컴퓨터(PC B)에서 접속하기

### 방법 A. `irssi` 클라이언트로 접속 (추천)

1. 터미널에서 `irssi`를 실행합니다:
   ```bash
   irssi
   ```
2. irssi 내부 입력창에서 서버에 접속합니다:
   ```text
   /connect <서버IP> 6667 1234
   ```
   *(예시: `/connect 10.12.3.45 6667 1234`)*
3. 닉네임 변경 및 채널 입장:
   ```text
   /nick evaluator
   /join #42
   /msg #42 안녕하세요!
   ```

---

### 방법 B. `nc` (Netcat)로 로우 레벨 프로토콜 접속

RFC 1459 규격에 맞는 등록 시퀀스를 직접 검증할 때 사용합니다:

1. 터미널에서 접속:
   ```bash
   nc <서버IP> 6667
   ```
2. 등록 명령어 전송 (엔터 치며 순서대로 입력):
   ```text
   PASS 1234
   NICK eval_user
   USER eval_user 0 * :Evaluation User
   ```
3. 채널 입장 및 메시지 전송:
   ```text
   JOIN #42
   PRIVMSG #42 :Netcat에서 보낸 메시지입니다.
   ```

## 3. [3단계] 42 평가 핵심 체크리스트 (Verification Checklist)

| 번호 | 테스트 항목 | 실행 방법 및 명령어 | 기대 동작 / 검증 포인트 |
| :---: | :--- | :--- | :--- |
| **1** | **다중 동시 접속** | PC A(서버)와 PC B(클라이언트)에서 각각 `irssi`로 동시 접속 | 서버 블로킹(멈춤) 없이 두 클라이언트 모두 정상 등록 |
| **2** | **비밀번호 검증** | 틀린 비밀번호로 `PASS wrong` 전송 | `464 ERR_PASSWDMISMATCH` 반환 및 연결 거부/종료 |
| **3** | **채널 브로드캐스팅** | 양쪽 모두 `/join #test` 후 한쪽에서 메시지 전송 | 상대방 화면에 실시간으로 메시지 표시 |
| **4** | **닉네임 변경 동기화** | 한쪽에서 `/nick newName` 실행 | 공유 중인 채널의 상대방 화면에 닉네임 변경 알림이 표시됨 |
| **5** | **채널 모드 제어** | 방장(Operator)이 `/mode #test +i` (초대전용) 설정 후 미초대자 입장 시도 | 초대전용 채널에 일반 유저 입장 불가 (`473 ERR_INVITEONLYCHAN`) |
| **6** | **초대 (INVITE)** | 방장이 `/invite <상대방>` 실행 후 상대방이 `/join` | 정상 입장 가능 확인 |
| **7** | **강퇴 (KICK)** | 방장이 `/kick #test <상대방>` 실행 | 대상 유저가 채널에서 퇴장 처리됨 |
| **8** | **정상 종료 (QUIT)** | 클라이언트에서 `/quit` 또는 `QUIT :bye` 전송 | 공유 채널 유저들에게 QUIT 알림 전송 및 서버 리소스(fd) 정리 |
| **9** | **비정상 종료 안정성** | 클라이언트 터미널에서 `Ctrl + C`로 강제 종료 | 서버가 크래시(Crash/SIGPIPE) 없이 정상 동작 유지 |

## 4. 💡 문제 해결 (Troubleshooting)

### Q1. 다른 컴퓨터에서 `Connection refused` 또는 타임아웃이 발생합니다.
1. **Ping 테스트**: 클라이언트 PC에서 `ping <서버IP>` 명령어로 물리적 통신이 가능한지 확인합니다.
2. **리눅스 방화벽(UFW) 해제**: 서버 PC에서 포트를 열어줍니다.
   ```bash
   sudo ufw allow 6667/tcp
   ```
3. **IP 재확인**: 서버 PC의 IP가 가상 IP(Docker 등)가 아닌 실제 랜선/Wi-Fi IP인지 다시 확인합니다.

### Q2. 비밀번호 인증 에러가 발생합니다.
* 서버 실행 시 입력한 비밀번호와 클라이언트의 `PASS` / `/connect` 비밀번호가 대소문자까지 정확히 일치하는지 확인하세요.
